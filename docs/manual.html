1. gitteam でできること

gitteam は、チームで GitHub を使うときの「決めごと」を 1 つの設定ファイル（gitteam.yaml）にまとめ、 ブラウザの画面（Web UI）またはコマンド（CLI）からその決めごとを GitHub とメンバーの PC に反映するツールです。 リポジトリの作成、メンバーへの権限付与、main ブランチの保護、コミットメッセージやブランチ名のルール、各メンバーの git 設定までを一度に整えます。

2. 動作環境と事前準備

必要なものバージョン入手先 / 確認方法
Python3.11 以上https://www.python.org/ 。python --version で確認
git2.23 以上https://git-scm.com/downloads 。git --version で確認
gh（GitHub CLI）2.47 以上https://cli.github.com/ 。gh --version で確認
GitHub アカウント-個人で使う場合は自分のアカウント、組織で使う場合は組織のオーナー権限

GitHub へのログイン（初回のみ）

gitteam は gh を通して GitHub に接続します。ターミナル（PowerShell やコマンドプロンプト）で次を実行し、ブラウザの指示に従ってログインしてください。

gh auth login

組織のチームやメンバーを操作する場合は、追加の権限が必要です。

gh auth refresh -s admin:org
GitHub のプランによる制限
無料プランでは非公開リポジトリに main ブランチの保護を設定できません。gitteam は自動でプランを調べ、使えない機能は理由を添えてスキップします。公開リポジトリにするか、有料プラン（個人は Pro、組織は Team 以上）にすると使えるようになります。

3. インストールと起動

いちばん簡単な方法（Windows）

  1. gitteam のフォルダーを開き、start_ui.bat をダブルクリックします。
  2. 初回は仮想環境の作成と必要なパッケージの導入が自動で行われます（数分かかります）。
  3. ブラウザが自動で開き、http://localhost:8501 に「はじめに」画面が表示されます。

macOS / Linux では ./start_ui.sh、PowerShell では .\start_ui.ps1 を実行します。

手動でインストールする場合

python -m venv .venv
.venv\Scripts\activate          # macOS / Linux: source .venv/bin/activate
pip install -e ".[ui]"
streamlit run ui/streamlit_app.py   # 画面を起動
gitteam --help                      # コマンドを使う場合
画面はこの PC からだけ使えます
画面（Web UI）には認証がないため、localhost のみで待ち受ける設定になっています。--server.address 0.0.0.0 などで他の PC から見えるようにしないでください。

終了するには

起動したターミナル（黒い画面）で Ctrl+C を押すか、ウィンドウを閉じます。ブラウザのタブを閉じただけでは終了しません。

4. 初期設定（4 ステップ）

「はじめに」画面は、必要な準備を上から順に案内します。進み具合のバーと各ステップの「完了 / 未完了」バッジで、今どこまで済んでいるかが分かります。

4.1 必要なツールと GitHub へのログイン

git、gh、GitHub へのログインが自動で点検されます。未検出のものには入手先が表示されます。ログインを済ませたら「もう一度確認する」を押してください。

4.2 チームの設定ファイルを作る

入力項目入れるもの例
GitHub をどのように使いますか？「個人アカウントで使う」「組織（Organization）で使う」「組織（GitHub Enterprise）で使う」から選択組織（Organization）で使う
オーナーリポジトリを所有するアカウント名。URL https://github.com/<ここ> の部分。個人なら自分のユーザー名（自動入力されます）、組織なら組織名my-org
保存場所通常は変更不要。プロジェクト配下またはユーザーの設定フォルダーのみ指定できますC:\work\gitteam.yaml

「設定ファイルを作成する」を押すと、すべての項目にコメント付きの gitteam.yaml が作られ、自動的に「信頼済み」として登録されます（9 章参照）。

4.3 メンバーを登録する

組織で使う場合は「チームの設定」画面のかんたん設定タブでチームを作り、メンバーの GitHub ユーザー名を登録します（7 章）。個人アカウントの場合は共同作業者を登録します。一人で使う場合、このステップは不要です。

登録後、「チームとメンバー」画面の「GitHub に反映する」で実際に GitHub 上のチームが作られ、メンバーに招待メールが届きます。

4.4 最初のリポジトリを作る

「リポジトリを作る」画面でリポジトリ名を入力し、「内容を確認する」を押します。これから行われる操作（例: リポジトリの作成、ファイルの配置、ラベルの作成、main ブランチの保護、権限の付与）が日本語の一覧で表示されるので、確認してから「この内容でリポジトリを作成・設定する」を押します。

6. 日々の作業

「日々の作業」画面は、開発中に毎日行う作業をチームのルールどおりに進めるためのものです。最初に「作業しているリポジトリの場所」（PC 上のフォルダー）を指定します。

ブランチを切る

  1. 「作業の種類」を選びます（feature=新機能、fix=バグ修正、hotfix=緊急修正、chore=雑務、docs=文書、refactor=整理、test=テスト、release=リリース準備）。
  2. 「作業内容」を入力します。日本語でも構いません。英数字に変換され、feature/add-login-page のようなブランチ名が自動で作られます。
  3. Issue 番号があれば入力すると feature/42-add-login-page の形になります。
  4. 「内容を確認する」→「このブランチを作成して切り替える」。

コミットメッセージ

コミットメッセージは「種類: 説明」の形で書きます（Conventional Commits）。入力欄に書くとその場で判定されます。

書き方判定理由
feat: ログイン画面を追加OK種類 feat、説明あり
fix(auth): トークン期限切れを修正OKスコープ（auth）付き
feat(api)!: v1 エンドポイントを削除OK! は互換性のない変更
ログイン画面を追加NG種類がない
feat: 追加した。NG末尾のピリオド（句点）は不可
wip: 作業中NGwip は許可された種類にない

種類の一覧: feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert（設定で変更可能）。

PR（プルリクエスト）とリリース

  • PR を出す: タイトルは空欄でも自動で付きます。今いるブランチをプッシュし、テンプレート・ラベル・レビュアーを設定して PR を作ります。
  • リリース: バージョン（例 1.4.0）を入力すると、main の今の状態にタグ v1.4.0 を付け、変更点をまとめた GitHub Release を公開します。main 以外のブランチや未コミットの変更があるときは止まります。

自動チェック（hooks）

「自動チェックを入れる」を実行すると、コミット時と push 時にルールを自動で検証する仕組みがリポジトリに入ります。「リポジトリに入れてチーム全員で共有」を選ぶと、他のメンバーも git config core.hooksPath .githooks の 1 行で同じチェックを使えます。

詳細（YAML を直接編集）

8. コマンド（CLI）

画面と同じ操作をターミナルからも実行できます。すべてのコマンドに --dry-run（-n）を付けると、実行される git / gh のコマンドを表示するだけで何も変更しません。

コマンド用途
gitteam doctor環境の点検
gitteam config init --owner NAME --mode org|org-enterprise|personal設定ファイルの作成
gitteam config validate / show / capabilities設定の検証 / 表示 / 使える機能
gitteam config trust / untrust / trusted作業フォルダーで見つかった設定の信頼登録 / 解除 / 一覧
gitteam repo init NAMEリポジトリの作成と標準の適用
gitteam repo settings|protect|access NAME、gitteam repo labels sync NAME [--prune]個別適用
gitteam team sync [--repo NAME] [--skip-repos]チーム・メンバー・権限の反映
gitteam team invite USER [--team T] [--repo R] [--permission push]招待
gitteam ops branch new TYPE "説明" [--issue N]ブランチ作成
gitteam ops branch check / gitteam ops commit checkルールの検証（違反時は終了コード 1）
gitteam ops pr create [--draft]PR 作成
gitteam ops release 1.4.0リリース
gitteam ops hooks install [--shared|--local]自動チェックの導入
gitteam dev setup --name "名前" --email you@example.comPC の git 設定
gitteam dev onboard --dir ~/work新メンバーのセットアップとクローン

9. 安全のしくみ

確認してから実行
2 段階
「内容を確認する」は何も変更せず、これから行う操作を一覧表示。「実行する」を押したときだけ反映されます
画面の公開範囲
この PC のみ
localhost だけで待ち受け。他の PC からは接続できません
設定ファイルの信頼
明示的に信頼
クローンしたリポジトリに入っていた設定は、確認して「信頼する」を押すまで使いません
認証情報
保存しない
GitHub への接続は gh に任せ、gitteam はトークンを持ちません

「未信頼の設定ファイル」と表示されたら

他の人が作ったリポジトリをクローンし、その中に gitteam.yaml が入っていた場合に表示されます。設定ファイルは git の設定や自動チェックの内容を変えられるため、 中身を確認してからサイドバーの「この設定ファイルを信頼する」を押してください（CLI では gitteam config trust）。自分で「はじめに」画面から作った設定は自動的に信頼されます。

設定に書けないもの

安全のため、設定の保存時に次の内容は拒否されます。

  • git にプログラムを実行させる設定（core.fsmonitor、core.sshCommand、credential.helper、core.hooksPath など）と、! で始まるエイリアス
  • ブランチ命名の正規表現や種別名などに含まれる引用符・セミコロン・空白などの特殊文字（自動チェックのスクリプトに埋め込まれるため）

詳しくは SECURITY.md を参照してください。

10. 困ったときは

症状原因対処
「GitHub にログインできていません」gh が未ログイン、またはトークン失効ターミナルで gh auth login を実行し、「はじめに」の「もう一度確認する」
「権限が足りません」組織の管理者でない、または gh に admin:org 権限がないgh auth refresh -s admin:org を実行。組織のオーナーに権限を確認
「見つかりませんでした」オーナー名・リポジトリ名・チーム名の綴り違い、またはアクセス権なし「状態を見る」の診断で owner の種別（User / Organization）と利用形態が合っているか確認
main ブランチの保護が「スキップ」される無料プランの非公開リポジトリ公開リポジトリにするか、有料プランへ。「使える機能の確認」で条件を表示できます
「未信頼の設定ファイル」作業フォルダーで見つかった設定が未信頼内容を確認し「この設定ファイルを信頼する」
「この場所の設定ファイルは使えません」許可された場所以外のパスを指定したプロジェクト配下、または ~/.config/gitteam/ に置く
コミットが拒否される（hooks）メッセージやブランチ名がルール違反「日々の作業」でメッセージを確認。feat: 説明 の形に直す
画面が古いまま / 変更が反映されない起動中のサーバーがファイル変更を拾っていないターミナルで Ctrl+C して start_ui.bat から起動し直す
ポート 8501 が使用中別の画面が起動している既存の画面を終了するか、streamlit run ui/streamlit_app.py --server.port 8502
「working tree is not clean」（リリース時）コミットしていない変更がある先にコミットまたは退避（stash）する
それでも解決しないとき
「状態を見る」→「診断を実行」の結果と、エラーの「詳細ログ」を添えて管理者に相談してください。詳細ログには実行したコマンドと GitHub からの応答がそのまま残ります（トークンは含まれません）。
